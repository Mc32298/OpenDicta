# OpenDicta Updater Release Notes

This app now uses Tauri's signed updater flow instead of the old manual GitHub release check.

## Required build-time environment

- `TAURI_UPDATER_PUBLIC_KEY`
  - Public key embedded in the app build.
  - Safe to commit or expose, but this repo currently expects it as a build variable.
- `TAURI_SIGNING_PRIVATE_KEY`
  - Private signing key used when producing updater artifacts.
  - Must never be committed.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
  - Optional password for the private signing key.

If your release pipeline uses different secret names, map them before invoking `tauri build`.

## GitHub Release assets

Every release must publish:

- The Windows installer/bundle artifact generated by Tauri
- Its signature file
- `latest.json`

The updater checks this static feed URL:

- `https://github.com/Mc32298/OpenDicta/releases/latest/download/latest.json`

## Key generation

Generate an updater keypair locally with the Tauri CLI and store the private key outside the repository.

Example:

```powershell
npm run tauri signer generate -- -w $HOME\\.tauri\\opendicta-updater.key
```

Then:

- set `TAURI_UPDATER_PUBLIC_KEY` from the generated `.pub` contents
- store the private key and password in your CI secrets

## Runtime behavior

- OpenDicta checks for updates on app startup
- If a newer signed release exists, the user is prompted to download it
- The installer runs in Windows `passive` mode
- After install, OpenDicta prompts for restart
